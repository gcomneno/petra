# PETRA VISION Structural Geometric Factorization (FGS) — Contract v0

## Status

Research contract for Gate 1B.

This document defines the bounded native Structural Geometric Factorization
(FGS) experiment before implementation. It is not a production API, a decoder
contract, or a theorem about arbitrary geometries.

## Research question

Can a valid canonical PETRA VISION geometry be decomposed directly into the
ordered canonical geometries of the immediate branches of its root, using
geometry alone, and then recomposed exactly?

The native claim is deliberately narrower than complete structural decoding.

## Existing geometric grammar

The frozen PETRA VISION geometry model represents an `OrthogonalGeometry` only
as a canonically ordered tuple of occupied integer-lattice cells.

There are no additional per-cell attributes in the current geometry record.

A terminal is encoded as the single occupied cell

```text
((0, 0),)
```

A non-terminal root is encoded as an ordered sequence of bays. Adjacent bays
share full-height vertical separators. Each child geometry is placed inside its
bay with the frozen horizontal and vertical clearances.

The left-to-right position of the bays is the geometric carrier of child order.

## Three factorization levels

Gate 1B keeps three levels separate.

1. **Structural oracle**

   `VisionShape` directly exposes its immediate ordered children.

   This is an evaluation oracle only.

2. **Decoder-mediated geometric factorization**

   Geometry is decoded to `VisionShape`, whose immediate children are then
   re-encoded as geometries.

   This is an admissible control but not the native claim.

3. **Native FGS**

   Immediate ordered factor geometries are extracted directly from occupied
   cells without first invoking the complete structural decoder.

   This is the research object evaluated by Gate 1B.

## Native input boundary

The native factorizer accepts exactly one canonical `OrthogonalGeometry`.

For Contract v0, canonical means:

- exact `OrthogonalGeometry` record;
- non-empty exact integer coordinate tuples;
- canonical coordinate ordering;
- no duplicate cells;
- minimum x coordinate equal to zero;
- minimum y coordinate equal to zero;
- geometry conforms to the frozen PETRA VISION geometric grammar.

Global translation tolerance is not part of the native Contract v0 success
criterion. Translation may be evaluated separately as a control.

The native factorizer must not receive or inspect:

- `VisionShape`;
- `Terminal`;
- `OrderedGroup`;
- PETRA native model objects;
- `decode_geometry`;
- shape codes;
- structural addresses;
- serialization;
- corpus indices;
- filenames;
- object identity;
- adapter metadata;
- annotated factor boundaries;
- any equivalent structural identity channel.

## Factor definition

For one valid non-terminal parent geometry, let the full-height columns be the
x coordinates occupied at every y coordinate of the parent extent.

Adjacent full-height columns define one root bay.

For each bay, its factor payload is the set of occupied cells strictly between
the two bounding full-height columns and strictly between the parent's bottom
and top frame rows.

The factor is the payload translated so that its minimum x and minimum y are
both zero and represented as a canonical `OrthogonalGeometry`.

Factors are emitted in increasing bay x position.

Therefore FGS is ordered and non-commutative.

Equal factor geometries occurring more than once remain separate occurrences.
Therefore FGS preserves multiplicity.

## Native result

Conceptually:

```text
FGS : OrthogonalGeometry -> tuple[OrthogonalGeometry, ...]
```

For the terminal geometry:

```text
FGS(((0, 0),)) = ()
```

For every valid non-terminal geometry, the result is a non-empty ordered tuple.

An empty factor tuple therefore denotes the irreducible terminal relative to
the current frozen grammar. No arithmetic prime-factorization analogy is
implied.

## Parent scaffold

Factor payload cells do not include the root container scaffold.

The parent scaffold consists of the cells generated by the root-level frame
and its full-height bay separators.

For a valid parent, every occupied source cell belongs to exactly one of:

1. the parent scaffold; or
2. one translated occurrence of exactly one immediate factor.

These ownership classes must be pairwise disjoint and their union must equal
the complete parent cell set.

This is the Gate 1B cell-ownership invariant.

Because the current `OrthogonalGeometry` record has no per-cell attributes,
there are no additional cell properties to preserve in Contract v0.

## Canonical recomposition

Recomposition accepts an ordered tuple of canonical factor geometries.

For an empty tuple it produces the canonical terminal geometry.

For a non-empty tuple:

1. obtain each factor width and height;
2. set parent height to the maximum factor height plus four;
3. begin with the left boundary at x = 0;
4. for each factor in order:
   - set the right boundary to
     `left_boundary + factor_width + 3`;
   - emit the corresponding root frame and separator cells;
   - place the factor at
     `x = left_boundary + 2`;
   - place its top at
     `y = parent_height - 3`;
   - advance the left boundary to the right boundary;
5. canonicalize cell ordering.

The result must use geometry only and must not call the structural encoder.

For every accepted canonical input `G`:

```text
recompose_fgs(FGS(G)) == G
```

Exact recomposition is mandatory, not merely shape equivalence.

## Recursive applicability

Every emitted factor is itself an `OrthogonalGeometry` and may be passed back
to native FGS.

A complete native FGS replay recursively applies the same geometric operation
until every branch reaches the terminal geometry.

Recursive replay may recover information isomorphic to the bounded structural
tree, but it must do so through repeated geometry-only factorization rather
than by invoking the existing complete structural decoder.

## Local validation

A non-terminal parent must satisfy at least the following root-level
conditions before factors are accepted:

- complete outer frame;
- first and last full-height boundaries coincide with the parent boundaries;
- at least two full-height boundaries;
- every adjacent boundary pair defines a legal-width bay;
- every bay contains a non-empty payload;
- horizontal child clearance is canonical;
- vertical child clearance is canonical;
- payload width exactly matches its bay;
- payload top alignment is canonical;
- normalized factors are exact `OrthogonalGeometry` values;
- factor occurrences do not overlap;
- scaffold and factor ownership are disjoint;
- scaffold plus translated factors exactly covers the source geometry;
- geometric recomposition exactly reproduces the input.

A geometry that passes root-level extraction but contains a malformed nested
factor must fail during recursive native replay.

No malformed input may be silently repaired.

## Structural oracle

For evaluation only, the expected immediate factors of a `VisionShape` are:

```text
tuple(encode_geometry(child) for child in shape.children)
```

and the expected terminal factor sequence is empty.

This oracle must remain outside the native FGS implementation boundary.

## Existing precursor evidence

The repository already contains an independent raw-cell path experiment that
extracts child payloads using geometry alone.

Across the bounded Phase 1 corpus it checks 574 non-root child paths and
asserts that every extracted normalized child-cell geometry equals the geometry
of the corresponding independent structural subshape.

This is precursor evidence for native geometric extraction.

It is not by itself a Gate 1B result because it does not establish the complete
FGS contract, malformed-input behavior, exact recomposition protocol,
identity-channel audit, or dedicated deterministic evidence artifacts.

## Phase 1 success criteria

Gate 1B requires all 110 Phase 1 geometries to satisfy simultaneously:

- exact immediate factor count;
- exact factor geometries;
- exact left-to-right factor order;
- multiplicity preservation;
- deterministic replay;
- exact scaffold/factor cell ownership;
- canonical normalized factors;
- recursive applicability;
- exact recomposition;
- correct terminal behavior;
- explicit malformed-input rejection;
- no forbidden identity or structural channel.

A numerical `110/110` result is insufficient if any invariant fails.

## Extended replay

Only after the Phase 1 contract is positive:

- replay separately on the 27 width-4 held-out forms;
- replay on the complete 137-form extended corpus;
- retain held-out results separately from aggregate extended results.

The width-4 geometry encoder remains an experimental research encoder and must
not silently modify the frozen production geometry contract.

## Required controls

The Gate 1B evidence must report separately:

- structural-oracle factors;
- decoder-mediated factors;
- native geometry-only factors;
- independent recomposition;
- recursive native replay;
- deterministic duplicate replay;
- malformed-input negative controls;
- identity-channel/source-boundary audit.

## Falsification criteria

Gate 1B remains negative or unresolved if any declared bounded geometry
requires:

- structural metadata to determine factor count or order;
- a shape code, serialization, address, corpus position, or object identity;
- ambiguous factor ownership without a declared geometry-only canonical rule;
- lost or duplicated occupied cells;
- factor overlap;
- non-canonical factor normalization;
- decoder-mediated extraction disguised as native extraction;
- silent repair of malformed geometry;
- failure of exact recomposition;
- inconsistent repeated replay.

Negative cases must remain visible in the evidence.

## Non-claims

A positive bounded Gate 1B result establishes only that native FGS is feasible
for the declared PETRA VISION geometry grammar and bounded corpora.

It does not establish:

- general or theorem-level unique factorization;
- arithmetic factorization;
- complete dynamic recognition;
- Gate 2 factor-graph semantics;
- spectral uniqueness;
- robustness to noise or adversarial geometry;
- factor-boundary stability outside the frozen grammar;
- production API readiness.
